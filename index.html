01 / Full-stack · Internship
CodeAtlas
I worked on CodeAtlas during my internship at PICT. It helps developers understand APIs and database schemas through interactive graphs instead of reading through files manually.
ReactExpressReactFlowDagre
Launch project ↗
Illustrative dependency graph
Technical details
Input and parsing
The platform accepts OpenAPI documents in YAML or JSON and SQL schema files. Backend parsers extract API endpoints, database entities and relationships from these inputs.
Backend and graph representation
Node.js and Express expose REST interfaces for the extracted information. Conceptually, entities and endpoints become graph nodes, while their relationships become edges, separating the source format from the visualization layer.
Frontend and validation
ReactFlow renders the interactive dependency graph; Dagre arranges connected nodes into a readable layout. A synthetic benchmark suite exercises the parsers and graph generation across different input structures.
02 / Full-stack · Interactive game
Memory Match
A memory game I built to explore React state management and backend development. Players can choose a difficulty, race against the clock and track their results on a leaderboard.
ReactNode.jsExpressSQLite
Play full game ↗
0 moves · Match the pairs
Technical details
Game engine
React manages the board, selected cards, matched pairs, moves and remaining time. The matching logic compares two selected cards and updates the game state. Difficulty changes the grid size (2×2, 4×4 or 8×8), time budget and move limit.
Client–server architecture
The React frontend handles gameplay while Node.js and Express provide REST APIs for game results, statistics and leaderboards. SQLite stores game records in a structured database table, allowing results to persist beyond the current browser session.

03 / Embedded systems
AquaTalk
An underwater optical wireless communication prototype that uses light to transfer messages between submerged devices.
ESP32LEDPhotodiodeOLED
Underwater optical link · illustration
Interactive simulation · not live hardware

Technical details
Transmitter and optical channel
An ESP32 and high-power LED form the transmitting side. In an optical communication link, information is represented by variations in emitted light rather than a wired connection.
Receiver and output
A photodiode converts incident light into an electrical signal. The prototype displays received messages on a 128×64 OLED. Underwater transmission was tested up to 10 cm.
Engineering considerations
Water attenuation, ambient light, alignment and receiver sensitivity influence link quality. The exact modulation and decoding implementation is not documented in the resume.


04 / Machine learning research
Student Depression Prediction
During my research internship at IIIT Una, I developed a machine learning pipeline using Kaggle survey data to study student depression prediction.
Machine learningEDAXGBoostClassification
Research workflow
Survey data↓Preprocessing & EDA↓Model evaluation↓XGBoost
84.7% reported model accuracy
Technical details
Data preparation
Exploratory data analysis was followed by missing-value handling, categorical encoding and numerical feature scaling to prepare survey features for classification.
Model comparison
I evaluated Logistic Regression, Decision Tree, Random Forest, Support Vector Machine and XGBoost. These models represent linear, tree-based, ensemble and margin-based classification approaches.
Evaluation
The optimized XGBoost model achieved 84.7% accuracy. Accuracy alone does not establish clinical validity; this is an academic research project, not a diagnostic tool.
